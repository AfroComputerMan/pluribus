**008_active_processes.sql** -- New SQLite migration:
```sql
CREATE TABLE IF NOT EXISTS active_processes (
  id          TEXT PRIMARY KEY,
  provider    TEXT NOT NULL,
  pid         INTEGER NOT NULL,
  thread_id   TEXT,
  spawned_at  TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%f', 'now'))
);
CREATE INDEX IF NOT EXISTS idx_active_processes_provider ON active_processes(provider);
```

**src-tauri/src/lib.rs** -- Add migration entry:
Add `Migration { version: 8, description: "active_processes_tracking", sql: include_str!("../migrations/008_active_processes.sql"), kind: MigrationKind::Up }` to the migrations vec after version 7.

**src/lib/db.ts** -- Add `db.processes` namespace:
- `db.processes.track(id: string, provider: string, pid: number, threadId: string | null): Promise<void>` -- INSERT into active_processes
- `db.processes.untrack(id: string): Promise<void>` -- DELETE from active_processes WHERE id = ?
- `db.processes.getAll(): Promise<ActiveProcess[]>` -- SELECT * FROM active_processes
- `db.processes.clearAll(): Promise<void>` -- DELETE FROM active_processes
- Import `ActiveProcess` from `@/lib/providers/types`

**agent-process-manager.ts** -- Centralized process lifecycle:
- `AgentProcessManager` class implementing:
  - `trackProcess(id: string, threadId: string, provider: string, pid: number): Promise<void>` -- writes to SQLite via db.processes.track, logs dev event
  - `untrackProcess(id: string): Promise<void>` -- removes from SQLite via db.processes.untrack
  - `cleanupOrphans(): Promise<number>` -- on startup: query db.processes.getAll(), for each stale PID attempt `kill(pid, 0)` check then `kill(pid, SIGTERM)` via Tauri shell `kill()`, clear the table, return count of killed processes. Log results. Use silent cleanup (no user notification per user decision).
  - `killAll(): Promise<void>` -- kill all tracked processes, clear table
  - `hasActiveProcesses(): Promise<boolean>` -- checks if active_processes table has rows
  - `getActiveAgentDescriptions(): Promise<Array<{ threadId: string; title?: string }>>` -- queries active_processes joined with threads for titles
- `createAgentProcessManager(): AgentProcessManager` factory
- NOTE: Sidecar ownership will be added in Plan 02 when the Agent SDK provider is implemented. For now, the process manager handles generic PID tracking only.
- For PID killing: Use Tauri's `Command.create("kill", ["-TERM", pid.toString()])` or track `Child` references in an in-memory Map alongside the SQLite PID records. The in-memory Map allows calling `child.kill()` directly for processes spawned in this session. The SQLite table handles crash recovery (orphans from previous sessions where we only have PIDs).
