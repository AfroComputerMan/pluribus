<task type="auto">
  <name>Task 2: Create Agent SDK provider implementation</name>
  <files>src/lib/providers/agent-sdk-provider.ts</files>
  <action>
Create `src/lib/providers/agent-sdk-provider.ts` implementing the AgentProvider interface. This is a FRESH implementation (user decision: do NOT extract from agent-sdk-adapter.ts), but use the existing adapter as reference for the NDJSON protocol and content accumulation patterns.

**Provider factory:** `createAgentSdkProvider(getSidecar: () => AgentSdkSidecar): AgentProvider`
- The provider receives a sidecar accessor function (process manager owns the sidecar per user decision)
- Provider does NOT spawn or kill the sidecar process

**Properties:**
- `id: "agent-sdk"`
- `displayName: "Agent SDK"`
- `capabilities: { supportsResume: true, supportsApproval: false, supportsSubAgents: true, supportsMcp: true, supportsEffort: true }`
- `supportedModels`: Import from `CLAUDE_MODELS` in models.ts, map to IDs: `CLAUDE_MODELS.map(m => m.id)`

**run(ctx: RunContext) implementation:**
- Generate a unique queryId (crypto.randomUUID())
- Build the NDJSON query message: `{ type: "query", id: queryId, prompt: ctx.prompt, sessionId: ctx.sessionId, model: ctx.model, cwd: ctx.cwd, configDir: ctx.configDir (if RunContext has it, otherwise omit) }`
- Send via sidecar.send(msg)
- Set up a Promise-based listener for sidecar outbound messages matching this queryId
- Accumulate content from `message` events, converting SidecarSdkMessage into ChatModelRunResult yields (follow the pattern in agent-sdk-adapter.ts for content part mapping: text blocks, tool calls, thinking blocks)
- On `done` event: save sessionId via `db.sessions.upsert()`, yield final result
- On `error` event: throw with error message
- Handle ctx.abortSignal: when aborted, send interrupt message `{ type: "interrupt", queryId }` and clean up
- Fire ctx.onDevEvent for each sidecar message (category: "sidecar", data: the message)

**AgentSdkSidecar class** (include in this file or as a separate internal class):
- Rewrite the sidecar management class fresh. It wraps `Command.sidecar("binaries/agent-sdk-bridge", [])` from Tauri shell plugin.
- `start(): Promise<Child>` -- spawns the sidecar, sets up stdout line buffering and NDJSON parsing, routes messages to registered handlers by queryId
- `send(msg: SidecarInbound): void` -- writes NDJSON line to stdin
- `shutdown(): Promise<void>` -- sends `{ type: "shutdown" }`, waits for process close (max 3s), then kills if needed
- `isAlive(): boolean` -- tracks whether the child process is alive
- `onMessage(queryId: string, handler): () => void` -- registers a handler for a queryId, returns unsubscribe function
- **Health check**: Periodic ping every 30s. If no pong within 5s, restart the sidecar. Use setInterval internally. Clear on shutdown.

Export `AgentSdkSidecar` so the process manager can own and create it.
