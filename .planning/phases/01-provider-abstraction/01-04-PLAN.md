**orchestrated-adapter.ts** -- The single ChatModelAdapter that replaces router-adapter.ts:

`createOrchestratedAdapter(registry: ProviderRegistry, processManager: AgentProcessManager): ChatModelAdapter`

Implementation of `run(options)`:
1. Extract threadId from `(options as any).unstable_threadId?.trim() ?? "__global__"`
2. Load thread config from SQLite: `db.threads.get(threadId)` for model, effort, cwd
3. Resolve model: `resolveModel(threadRow?.model ?? null)` from models.ts
4. Resolve effort: `resolveEffort(threadRow?.effort ?? null)` from models.ts
5. Select provider: `registry.getProviderForModel(model)`
6. Extract prompt via `extractUserPrompt(options.messages)` from providers/shared.ts. If empty, return.
7. Resolve session: `db.sessions.get(threadId)` for sessionId
8. Resolve cwd: `threadRow?.cwd ?? await homeDir()`
9. Set status to "running" via `useThreadStatusStore.getState().setStatus(threadId, "running", title)`
10. Build RunContext and call `yield* provider.run(ctx)`
11. On success: set status "idle"
12. On error: set status "error", show crash toast via `sonner` with thread name (per user decision: "Immediate toast notification + error status badge when an agent process crashes mid-run"), throw error
13. Track PID via processManager (for Agent SDK: after sidecar query starts; for Codex: call getCodexPid() after invoke)

**RuntimeProvider.tsx** -- Replace routing:
1. Remove import of `createRouterAdapter` from `@/lib/router-adapter`
2. Create the provider registry and process manager as module-level singletons:
   ```typescript
   const registry = createProviderRegistry();
   const processManager = createAgentProcessManager();
   const sidecar = new AgentSdkSidecar();
   registry.register(createAgentSdkProvider(() => sidecar));
   registry.register(createCodexProvider());
   ```
3. Run orphan cleanup on module load: `processManager.cleanupOrphans().then(n => { if (n > 0) console.log(`Cleaned up ${n} orphan processes`); });`
4. Update `useRuntimeHook` to use `createOrchestratedAdapter(registry, processManager)`
5. Keep all existing providers (AssistantRuntimeProvider, TooltipProvider, Toaster, ApprovalBanner, ThreadStatusToasts)

**Process manager sidecar ownership:**
- The process manager should track the sidecar PID after it starts. Add a method or wire it so that when the sidecar spawns, its Child PID is registered via `processManager.trackProcess("sidecar", null, "agent-sdk", pid)`.
