<objective>
Build the AgentRegistry class and the extended Zustand status store. The registry is the central coordinator for all agent lifecycle operations (spawn, kill, restart, query), delegating to the ConcurrencyGovernor for slot management, AgentProcessManager for PID tracking, and ProviderRegistry for model routing. The status store replaces thread-status-store.ts with the 5-status model and dual Zustand+SQLite persistence.

Purpose: This is the core of Phase 2 -- the registry is what enables multi-agent orchestration. Everything else (governor, persistence, status FSM) feeds into it.
Output: Working AgentRegistry with tested spawn/kill/restart/query operations, plus reactive status store.
</objective>

<task type="auto">
  <name>Task 2: AgentRegistry class with spawn/kill/restart/query</name>
  <files>src/lib/orchestration/agent-registry.ts, tests/agent-registry.test.ts</files>
  <action>
    Create the AgentRegistry as a class that accepts dependencies via constructor (for testability):

    ```typescript
    interface AgentRegistryDeps {
      governor: ConcurrencyGovernor;
      processManager: AgentProcessManager;
      providerRegistry: ProviderRegistry;
      statusStore: typeof useAgentStatusStore;
      writeSerializer: WriteSerializer;
    }
    ```

    1. Create `src/lib/orchestration/agent-registry.ts`:
       - `class AgentRegistry`:
         - `constructor(deps: AgentRegistryDeps)`
         - `async spawn(threadId: string, cwd: string, model: string): Promise<'running' | 'queued'>`:
           a. Call governor.acquire(threadId)
           b. If 'queued': set status to 'queued' in store + DB (via writeSerializer), return 'queued'
           c. If 'acquired': set status to 'running' in store + DB, store cwd + providerType in DB, return 'running'
           d. The actual provider.run() is NOT called here -- that happens in OrchestratedAdapter. The registry just manages slots and status.
         - `async kill(threadId: string): Promise<void>`:
           a. Kill process via processManager (if tracked)
           b. Set status to 'error' in store + DB
           c. Release governor slot
           d. If a queued agent was promoted: set promoted agent's status to 'running' in store + DB
         - `async restart(threadId: string): Promise<'running' | 'queued'>`:
           a. Load thread from DB (get cwd, model)
           b. Kill existing process if any (without releasing governor slot -- we want to reuse it)
           c. Set status to 'running' in store + DB with errorHint cleared
           d. Return status
         - `cancelQueued(threadId: string): boolean`:
           a. Call governor.cancelQueued(threadId)
           b. If cancelled: remove status from store, clear DB status
           c. Return success
         - `markCompleted(threadId: string): void`:
           a. Set status to 'completed' in store + DB
           b. Release governor slot
           c. Promote next queued agent if any
         - `markError(threadId: string, errorHint?: string): void`:
           a. Set status to 'error' in store + DB
           b. Release governor slot
           c. Promote next queued agent if any
         - `markWaitingApproval(threadId: string): void` / `markApprovalGranted(threadId: string): void`
         - `getStatus(threadId: string): AgentStatusRecord | undefined`
         - `listActive(): Array<{ threadId: string } & AgentStatusRecord>`
         - `async initFromDb(): Promise<void>`:
           a. Load all threads with non-null agent_status from DB
           b. Mark any previously-running agents as 'error' with errorHint 'process lost' (per user decision: restart recovery)
           c. Load statuses into store via loadFromDb
           d. Run auto-archive: `db.threads.archiveStaleCompleted(7)` (per user decision: 7-day auto-archive)
       - `export function createAgentRegistry(deps: AgentRegistryDeps): AgentRegistry`

    2. Write `tests/agent-registry.test.ts`:
       - Use mock/stub deps (mock processManager, mock providerRegistry, real governor, real writeSerializer with no-op fn)
       - Test spawn: acquires governor slot, sets status to 'running'
       - Test spawn at capacity: 6th spawn returns 'queued'
       - Test kill: releases slot, promotes queued agent
       - Test restart: loads from DB mock, re-sets status
       - Test cancelQueued: removes from queue
       - Test markCompleted: releases slot, promotes queued
       - Test initFromDb: marks previously-running as 'error' with 'process lost'
       - Test cwd stored per thread (ORCH-08)

    3. Run tests.

    Key design decision: The registry does NOT call provider.run() -- it only manages slots, status, and persistence. The OrchestratedAdapter continues to call provider.run() but checks with the registry for slot availability and status updates. This separation keeps the registry testable without needing real providers.
