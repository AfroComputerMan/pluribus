<task type="auto" tdd="true">
  <name>Task 1: Vitest setup + ConcurrencyGovernor (TDD)</name>
  <files>vitest.config.ts, package.json, src/lib/orchestration/concurrency-governor.ts, tests/concurrency-governor.test.ts</files>
  <behavior>
    - acquire() returns 'acquired' when fewer than 5 active agents
    - acquire() returns 'queued' when 5 agents are already active
    - release() promotes the next queued agent in FIFO order
    - cancelQueued() removes a specific agent from the queue, returns true; returns false if not found
    - release() with empty queue does not error
    - activeCount and queuedCount are accurate
    - Double-acquire for same threadId is idempotent (or handled gracefully)
    - release() for a non-active threadId does not error
  </behavior>
  <action>
    1. Install vitest: `bun add -d vitest`
    2. Create `vitest.config.ts` with node environment, `tests/**/*.test.ts` include pattern, and `@` path alias pointing to `src/`
    3. RED: Write `tests/concurrency-governor.test.ts` with tests for all behaviors listed above. Tests import `ConcurrencyGovernor` from `@/lib/orchestration/concurrency-governor`. Run tests -- all fail.
    4. GREEN: Create `src/lib/orchestration/concurrency-governor.ts` implementing:
       - `constructor()` with hardcoded `maxConcurrent = 5` (per user decision: NOT configurable)
       - `acquire(threadId: string): 'acquired' | 'queued'` -- synchronous return, not async. If queued, stores a resolve callback for later promotion.
       - `release(threadId: string): string | null` -- removes from active set, promotes next from queue if any, returns promoted threadId or null
       - `cancelQueued(threadId: string): boolean` -- removes from queue
       - `get activeCount(): number` and `get queuedCount(): number` getters
       - Internal: `active: Set<string>`, `queue: Array<{ threadId: string; onPromoted: () => void }>`
    5. Run tests -- all pass.
    6. REFACTOR if needed.

    Note: The governor's `acquire()` is synchronous (returns immediately). The caller (AgentRegistry) handles the async "wait for promotion" via the `onPromoted` callback pattern. This keeps the governor testable without async complexity.
  </action>
  <verify>
    <automated>bunx vitest run tests/concurrency-governor.test.ts --reporter=verbose</automated>
  </verify>
  <done>Vitest runs successfully. ConcurrencyGovernor passes all tests: 5-slot limit, FIFO queue promotion, cancellation, edge cases.</done>
</task>

    AgentStatus:
    - Valid transitions: queued->running, queued->error, running->completed, running->error, running->waiting-approval, waiting-approval->running, waiting-approval->error, completed->running, error->running, error->queued
    - Invalid transitions are rejected: e.g., queued->completed, completed->error, completed->queued
    - AgentStatus type is 'running' | 'error' | 'waiting-approval' | 'completed' | 'queued' (no 'idle')
  </behavior>

    3. Run write-serializer tests -- all pass.
